# Корпус и EDA: задачи 10 и 8

## Запуск

Из корня проекта, Python 3.12 и uv:

```sh
uv sync --locked --only-group corpus-light
uv run --only-group corpus-light python scripts/prepare_corpus.py
uv run --only-group corpus-light python scripts/eda.py
```

Затем открыть `notebooks/EDA.ipynb` с ядром проектного `.venv`.
Первый запуск подготовки скачивает только токенизатор BGE-M3; его ревизия и
SHA-256 закреплены в коде. Веса модели не нужны.

## Какие файлы за что отвечают

| Файл | Назначение |
|---|---|
| `scripts/prepare_corpus.py` | Чтение ODT, очистка, выбор уникальных источников, структура, anchors и разрешение ссылок |
| `scripts/chunk_corpus.py` | Вызывается подготовкой: фрагменты с полным входом BGE-M3 не длиннее 512 токенов |
| `scripts/eda.py` | Частоты, размеры, длины, аномалии и статистика ссылок |
| `scripts/refresh_status.py` | Необязательная проверка внешних карточек; запускать отдельно перед подготовкой |
| `data/legal_status.csv` | Статус всего акта, дата, URL и основание; проверенные вручную записи сохраняются при обновлении |
| `notebooks/EDA.ipynb` | Отдельные разделы для 845-П и всех источников, 12 графиков и пример перехода по ссылке |
| `pyproject.toml`, `uv.lock` | Зависимости группы `corpus-light` и закреплённые версии |

`data/raw` — существующие исходники команды. Парсится только ODT: PDF и RTF
не увеличивают количество документов. Совпадения текста исключаются по хешу,
тождество акта определяется издателем, видом, датой и номером. Конфликтующие
редакции исключаются до выбора источника.

## Выходные данные

В `data/processed/corpus/`:

- `documents.jsonl` — реестр 93 исходников; `selected=true` у 90 источников
  (88 актов и 2 справочных материалов). Остальные — дубль, карточка и навигация.
- `units.jsonl` — 24 962 структурные единицы с исходными блоками, иерархией,
  текстом, таблицами и закладками. У 845-П — 369 единиц.
- `chunks.jsonl` — 20 405 фрагментов, включая 411 для 845-П. `unit_id` ведёт
  к исходной единице, `start:end` — к точному фрагменту её текста.
  Индексировать следует `embedding_text`; максимум проверенного входа — 508 токенов.
- `links.jsonl` — 67 259 вхождений гиперссылок. Пара «документ + anchor»
  разрешается в `target_unit_id`, `target_span` и пересекающиеся `target_chunk_ids`.
- `media/` — изображения по хешу содержимого, включая формулы без OCR.

`data/eda/main/` и `data/eda/all/` — таблицы и сводки двух выборок;
`data/eda/documents.csv` — общий реестр для просмотра. Старые выходы
`data/processed/845_p/` и плоские таблицы EDA заменены этими каталогами.

## Принципы и ограничения

Из подхода команды в коммите `fe5e43b` использованы иерархия и продолжение
текущего пункта. Docling-пайплайн не копируется: существующий ODT-парсер
сохраняет закладки всех источников. Перечни `1)` остаются внутри пункта;
заголовки передаются как контекст и не становятся отдельными чанками.
Редакторские вставки отделяются по стилям экспорта ГАРАНТ; закладки перед
ними переносятся к следующему нормативному блоку. Продолжение возвращается
в исходный пункт. Полные названия сохранены, контекст чанка ограничен 96 токенами.

Все файловые цели прямых гиперссылок 845-П уже есть в исходниках. Ссылки
из остальных документов рекурсивно не загружаются. Заголовок может иметь
`target_unit_id` без чанка: его содержание получают через дочерние `parent_id`.
Повторные номера форм и сносок получают `occurrence` и отмечаются в EDA;
это не означает дублирования самого акта. Большие таблицы могут делиться
внутри строки; целая таблица остаётся в структурной единице.

Проверка статусов от 08.11.2026: 15 отменённых актов, 73 неподтверждённых,
2 справочных материала. `unknown` не означает «действует», в том числе для
845-П. Частичная отмена не считается полной. URL и основания находятся
в CSV. Достоверная дата редакции ODT не установлена (`edition_date=null`).
Необязательное обновление: `uv run --only-group corpus-light python
scripts/refresh_status.py`, затем повторить подготовку и EDA. Ручные отметки
требуют отдельной повторной проверки; их дата автоматически не обновляется.

Проверены сохранность всех исходных блоков, закладок и изображений, уникальность
ID, наличие родителей, покрытие индексируемого текста чанками, точные диапазоны
и лимит токенов каждого чанка. Ноутбук исполнен целиком; Ruff прошёл.
Отдельный набор тестов и генераторы отчётов не добавлялись.
